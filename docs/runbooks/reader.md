# Document reader

Read this before changing reader ingest, text-to-speech conversion, playback, progress, the `/reader` page, or the Reader chat.

## Storage and modules

- Speech-ready JSON: `/home/dave/octavius-reader/`; pasted-text originals: `/home/dave/octavius-reader/pasted/<doc_id>-<slug>.md`; appendices: `<reader_dir>/appendices/<id>/<seq>-<stamp>.md`; metadata: `reader_documents` table.
- Entry points `reader_ingest_service.py` → source handlers `reader_ingest_handlers.py` → metadata `reader_store.py` → markdown-to-speech `reader_text.py` → playback `reader_playback.py` (WS side: `ws_reader.py`). Look-ups for chat: `local_tool_reader_lookup.py`. Source sniffing: `document_sources.py` (PDFs detected by content, not suffix).
- Ingest jobs are in-memory background tasks: on startup `fail_stale_processing_documents` marks leftover `processing` rows failed; recovery is manual retry (`POST /api/reader/documents/{id}/retry`, which replays stored source metadata).

## Sources and ingest

- Accepts local files, URLs, inbox items and **raw pasted text**. The document list auto-polls while anything is `processing`.
- **`/reader`'s add box** (since 2026-11-10): "+" opens a file picker; the file goes through `POST /api/media/upload` (works from any device) and is added by the returned spool path. The checkmark stays disabled until something is picked or typed.
- **Temporary** (`temporary: true` on `POST /api/reader/documents`, strict bool; `reader_documents.temporary`), for a file, path, URL or pasted text: `reader_store.purge_temporary_documents` deletes it once read to the end or 24 h after adding, on startup and before each library listing (never while `processing`), together with its pasted-text or uploaded source. A path Dave typed is never removed.
- **Pasted text** (`source: "text"`) is written out by `start_text_ingest` and recorded as `source_path`, which is what makes it retryable (`start_retry_task`'s `markdown` branch re-reads it). Best-effort: a write failure costs retryability, never the document. Both the paste box and the agent's `read_document(text=...)` go through `start_text_ingest`, so both get title derivation (`document_sources.derive_title_from_text`) and persistence.
- **HTML** goes through trafilatura as **markdown with tables** (since 2026-11-09; `txt` joined paragraphs with single newlines, making a whole article one chunk). `reader_ingest_handlers.extract_article_text` first prunes elements whose class/id has a `comment(s)` or `newsletter` token (`include_comments=False` missed Tom's Hardware's XenForo widget), rejoins tables trafilatura 2.0 writes one cell per line, drops short "Follow us on Google News"/newsletter paragraphs, prunes link lists under "Read more"/"Related"/"Top stories" headings, and when one `<article>` dominates (1500+ chars, 3x any other) extracts from it alone with nested `<article>`s removed (The Register wraps teaser cards in `<article>`; trafilatura read only "Top stories"). Comments are never read.
- PDFs convert through docproc (see [media-turns.md](media-turns.md)); conversion-output lookup tolerates mismatched filenames; arXiv `/pdf/` downloads get a `.pdf` suffix; `read_document` starts the conversion, not just a DB row.

## Text to speech

- Inline `$...$` counts as math only under Pandoc's rule (as `static/math-render.js`): no space inside either dollar, no digit after the closing one. ("$2,400 ... $900" used to send a whole article through the math LLM and then `strip_latex` deleted every `$`.)
- Math-heavy paragraphs go to the reader LLM (endpoints and failover: [model-routing.md](model-routing.md)); others are cleaned locally (`clean_for_speech`, which also strips citations/LaTeX).
- `reader_text.join_page_breaks` rejoins a paragraph a PDF page break split mid-sentence (ends in a word, comma or hyphen and the next prose paragraph starts lower case, or it ended on a comma), moving any caption/image/table/page number found between the halves after it. Documents converted before 2026-10-31 keep their splits.
- **Tables and figures** (since 2026-10-31): a markdown table is spoken as its caption ("Table 2: ...", from the adjacent `Table N`/`Tab. N` paragraph or a caption line directly above) plus one overview sentence from the reader LLM (thinking off; it answers `NONE` when the caption suffices). No caption: "A table." + overview; every endpoint down: caption only, or "A table with N rows.". An image `![...](...)` is never read as its filename: it is spoken as its `Figure N`/`Fig. N` caption plus a 1-2 sentence description from the **vision chain** when the file resolves (absolute, or relative to `source_dir` / `original_md_path`'s parent; image types only, ≤ 4 MB; remote URLs never fetched). No file or vision failure: caption only; neither: silence. `group_floats` keeps the caption paragraph in its float's chunk so it is not read twice. `source_text` keeps the raw table and link. Converted PDFs get captions only — docproc's markdown has no image links (`docs/HANDOFF-docproc-images.md`).
- Sections carry `level` (1-3 from `#`/`##`/`###`) for the table of contents; older documents have none (clients treat it as 1). `scripts/reader-backfill-heading-levels [--apply]` restores it where the source markdown still exists.
- Documents converted earlier keep their old speech until retried.

## Playback and progress

- Streamed sentence by sentence over the WS with position sync (`reader_play` → binary audio; `reader_position`, `reader_audio_done`).
- `reader_pause`/`reader_stop` may carry `doc_id`/`chunk_index`/`sentence_index` (since 2026-10-30) — the sentence the client was *hearing*. Playback synthesises far ahead, so the server saves that (`save_heard_position`, after the cancel) instead of its run-ahead place. Older clients omit them.
- **Paced** (`reader_play {paced: true}`): the stream stays at most `READER_AHEAD` (3) sentences past the last `reader_heard {seq, doc_id, chunk_index, sentence_index, sentence_global}` (sent as each sentence *starts*). A paced stream writes no position of its own and marks the document finished only once the last sentence is heard. `/reader` always paces; Android does not.
- **Download** (`reader_play {download: true}`, strict `is True`, since 2026-11-02): streams as before but writes nothing to place/progress and ignores `paced` — for clients caching audio offline.
- **Progress**: `reader_documents.total_sentences` / `progress_sentences` (sentences before the saved place, blanks included; equal to the total once read to the end, while `last_chunk`/`last_sentence` rewind to 0 so the next play starts over). Playback writes them per sentence; `_write_speech` recomputes them on ingest/append/replace; rows from before 2026-10-30 are backfilled lazily by `list_documents` (and derived in `GET /documents/{id}`).
- `POST /api/reader/documents/{id}/finished {"finished": true|false}` (`reader_store.set_finished`, ready documents only, strict bool) marks finished or unread without playing; both rewind to the start. `/reader` has a header button and row action; the open document's playback stops first.

## Append, replace, rename

- **Append** (`append_to_reader_document` tool, `POST /api/reader/documents/{id}/append {"text"|"path", "replace"?}`) is for a partial pull (sign-in pop-up, paywall teaser). `reader_text.append_to_document` is **incremental**: only new text is chunked and math-converted; existing chunks keep bytes and indices so `last_chunk`/`last_sentence` still point where Dave left off (re-chunking could re-split a section that grows past three paragraphs).
- `replace=true` rebuilds from the new text alone (when what the reader holds *is* the sign-in page). `replace` is parsed strictly (`"false"` is false; `bool("false")` would destructively rebuild).
- A `failed` document may be appended to (that is the sign-in-wall fix); a `processing` one 409s. The status flip is a conditional UPDATE (`reader_store.claim_document_for_processing`) so two appends cannot both launch a job.
- **Atomic**: the appendix file is written only after conversion succeeds, just before the speech file is replaced (temp + `os.replace`). A failed append leaves a `ready` document `ready` with the failure in `error` and nothing orphaned — clients must treat `ready` + `error` as failure.
- `ingest_document` folds appendices onto the base text, so a **retry** (which replays the original source) keeps appended text — persistence is mandatory. A `replace` leaves a `REPLACED` marker: `with_appendices` drops the base text and `start_retry_task` skips the source replay (a URL would hit the wall again).
- A `path` is read like file ingest (HTML via trafilatura); PDFs are refused — read them as their own document.
- **Rename** (`PATCH /api/reader/documents/{id} {"title": ...}`, `reader_ingest_service.rename_reader_document` → `reader_text.rename_document`), any status: stripped, rejected if blank or > 200 chars, written to the row; the speech JSON's title is rewritten too (same atomic helper), but a missing/unreadable speech file is not an error. Nothing reads the JSON title, so it is kept consistent cheaply: while `processing` the rename leaves the JSON to the job, and `_write_speech` re-reads the row's title just before writing.
- Both `/reader` and Android expose append / replace / rename (an edit panel on ready/failed cards and in the player), polling until the document settles.

## Original view (since 2026-11-04)

`GET /api/reader/documents/{id}` includes each chunk's `source_text` where stored; `/reader` renders it (tables, KaTeX) by default, with a header Original/Reading switch (`V`, remembered) and a per-chunk pill. No sentence map exists from original to spoken text, so in Original view place and playback highlight per chunk; a click moves the place to the likeliest sentence (`OctaviusReaderOriginal.sentenceAt`: words around the click matched against the spoken sentences, else the click's relative position — what happens inside math); a selection names whole chunks for the chat. Documents converted before 2026-10-31 have no `source_text`; the switch is hidden for them. Rail and chat panel resize on wide screens (drag, arrow keys on the focused handle, double-click to reset; `railW`/`chatW` in `octavius-reader-prefs`). Rendering rules: [frontend.md](frontend.md).

## Reader chat (since 2026-10-31)

- The panel (`static/reader-chat.js`) opens its own `/ws` and sends `doc_chat_open`; the conversation is keyed `reader-doc:<id>` (`source` `reader`), so each document has one chat that resumes; "New chat" renames the key to `reader-doc:<id>:<conv id>`. Turns run on the pi brain; the native brain gets no document context.
- The document is never sent whole: `place_context` gives the paragraph (chunk) before, Dave's place, and the paragraph after, each capped and quoted in `<document_excerpt>` with `<`/`>`/`"` neutralised. The place comes from `doc_chat_position`: a selection made since the place last moved (`end_chunk_index`/`end_sentence_index`; panel shows "About your selection"), else the marked sentence (a click while paused moves it without telling the server). Passage text is rebuilt server-side by index, never taken from the browser. No position → the saved place.
- Three look-up tools over the speech JSON (`reader_document_outline`, `read_reader_document`, `search_reader_document`); in a Reader chat they read only its own document and prefer `source_text` (LaTeX and citations intact) when present.
- **Citations** (since 2026-11-01): chunks are labelled `§N`; `place_context` ends with `CITE_RULE` (last, just before Dave's message — placed earlier, the 12B ignored it), asking for `[§N]` at the end of document-based sentences; look-up results repeat a one-line reminder. The panel turns tags into buttons calling `OctaviusReader.peek(N)` (scroll and highlight that chunk; place and playback untouched; follow turns off). A number the document lacks renders struck out. Citations are chunk-level (a chunk is up to three paragraphs). Checked on a synthetic paper: all four models cited correctly on 12/12.
- **Pre-turn search** (since 2026-11-01): the note also carries the section outline, a rule never to call something absent without searching, and the three chunks outside the passage best matching Dave's message (stop words dropped, light stemming, small synonym list; `local_tool_reader_lookup._rank`). His previous message only breaks ties, or stands in when the new one has no words of its own (counted equally, a follow-up's leftovers pushed out the defining paragraph). Without it the thinking-off 12B answered "not mentioned" to questions answered 6-12 chunks away. Per-document embedding search is deferred (`docs/status.md`).
- **Model menu** (`PiBrainSettings.reader_models`, `OCTAVIUS_PI_READER_MODELS`, JSON `[{id, label, model, thinking}]`): default **gemma4-12b with thinking off** (first word in ~1-2 s where the 26B thought for 8-17 s; the document anchors it), then gemma4-26b-a4b, qwen3.8-27b and glm-5.3-flash with the process's own thinking level. The panel remembers the choice (localStorage) and sends it on `doc_chat_open`. Mechanics: [pi-brain.md](pi-brain.md).
- **Privacy**: a Reader chat turn carries **no memory block** (the document never taints, so memory facts beside it would be private data the guard cannot see). Because the chat can read a document back, the model's file-path tools (`read_document`, `append_to_reader_document`, `process_pdf`) only accept files under the downloads folders, the media spool, `/media/extra_stuff/papers` or `~/school_lab`, with no hidden path component (`local_tool_reader.tool_source_path`). Paths Dave types into `/reader` or Android (REST) are unrestricted.
- Typed turns are silent (`tts:false`); spoken ones use the main page's voice (`octavius-prefs`); a turn pauses reading first; `c` opens the panel. It talks to `reader-app.js` only through `window.OctaviusReader` (`currentDoc`, `heardPlace`, `pause`, `onDocChange`, `peek`).
- **Known limitation**: the same document's chat open in two tabs shares one pi process, and switching documents in one tab discards it under the other's running turn (not worth cross-tab coordination yet).
